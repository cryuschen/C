## 运行与交付

在本目录执行下列命令。入口按自身位置定位工程，可从其他目录用完整脚本路径启动。

```bash
# 核对交付文件字节，不重新计算
python3 main.py --stage integrity

# 执行三题58项回归测试和已保存结果的数值审计
python3 main.py --stage verify

# 完整重新计算三题，并重绘第一题固定图4/5
python3 main.py --stage all
```

可单独选择 `q1`、`q2`、`q3`、`report`、`figures` 阶段。`all`及单题计算会更新工程中的对应结果，第二题包含1999次块内置换；不是快速验收命令。`verify`会刷新原工程的测试日志和审计清单。三题优化在上一轮分阶段执行过；本次合并重新运行第三题完整流程，第一、二题只执行回归与数值审计。

已有本机环境会自动识别；在新机器上可在本目录新建虚拟环境：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r 完整工程/requirements.txt
.venv/bin/python main.py --stage verify
```

Windows使用 `python` 和 `.venv\Scripts\python.exe`。依赖范围见[requirements.txt](完整工程/requirements.txt)，本次验证的实际版本见[环境记录](验收与清单/运行环境.json)。绘图需要中文字体，例如Noto Sans CJK SC。原工程的旧说明中 `.venv/bin/python` 命令假定该工程内另有虚拟环境；本次整理后的本机环境位于外层，推荐使用本页统一入口。

文件更新后应先验收，再刷新哈希和交付包：

```bash
python3 release.py --write-manifest --check --zip
```

该命令打包最终版整个目录，不包含本机环境与缓存。哈希清单只证明文件一致性，不替代模型验收。三题当前仍是两名受试者内部研究；Q1门控存在去噪与失真取舍，Q2未建立稳定识别优势，Q3功能状态与仿真不能证明海马来源，实测正误与超时状态仍未知。
